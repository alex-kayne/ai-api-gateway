# Решение: AI API Gateway

## Выбранное задание

Реализован API-шлюз к OpenRouter. Сервис принимает запросы на получение chat completion, проверяет API-ключ клиента в Redis и ограничивает каждого пользователя пятью запросами за минуту.

## Логика решения

Приложение разделено на HTTP-слой, бизнес-логику и адаптеры внешних систем:

- `app/routes.py` принимает запросы и преобразует ожидаемые ошибки в корректные HTTP-ответы;
- `app/dependencies.py` извлекает Bearer-токен, запускает авторизацию и проверку лимита до вызова целевой ручки;
- `app/services/gateway.py` хранит правила предметной области: лимит `5` запросов за `60` секунд и модель по умолчанию `openrouter/free`;
- `app/services/infrastructure.py` изолирует Redis и HTTP-вызов OpenRouter;
- `app/settings.py` читает конфигурацию из переменных окружения или `.env`.

Такое разделение позволяет тестировать правила шлюза без запущенных Redis и OpenRouter: тесты передают в `GatewayService` простой объект-заглушку.

## Алгоритм обработки `POST /v1/chat/completions`

1. Из заголовка `Authorization` извлекается токен формата `Bearer <API key>`. Отсутствующий или некорректный заголовок приводит к `401`.
2. По ключу Redis `api_key:<API key>` находится пользователь. Если ключ не зарегистрирован, возвращается `401`.
3. Для пользователя атомарно увеличивается счётчик `rate_limit:<user_id>` в Redis. При первом запросе этому ключу назначается TTL 60 секунд.
4. Если значение счётчика больше 5, шлюз прекращает обработку и отвечает `429 Too Many Requests`. В заголовок `Retry-After` записывается оставшийся TTL.
5. Тело запроса проверяется как JSON-объект; иные данные получают `422 Unprocessable Entity`.
6. Если поле `model` отсутствует, устанавливается `openrouter/free`.
7. Запрос пересылается в OpenRouter с серверным ключом `OPENROUTER_API_KEY`. Статус, тело и `Content-Type` ответа передаются клиенту. Сетевая ошибка OpenRouter преобразуется в `502 Bad Gateway`.

## Почему лимит атомарный

Инкремент и назначение TTL выполняются Lua-скриптом Redis за одну операцию:

```lua
local current = redis.call('INCR', KEYS[1])
if current == 1 then redis.call('EXPIRE', KEYS[1], ARGV[1]) end
return {current, redis.call('TTL', KEYS[1])}
```

Это исключает гонку между параллельными запросами одного пользователя: ни один запрос не может отдельно прочитать устаревшее значение счётчика или повторно задать окно.

## Проверка

Автотесты проверяют ключевые инварианты: лимит составляет ровно 5 запросов за 60 секунд, пятый запрос проходит, шестой получает ошибку лимита с TTL, неизвестный ключ отклоняется, а модель по умолчанию добавляется к запросу.

```bash
pytest -q
```
